This adapter issues only function04 reads: MAC identity at offset0/count6, then one response at offset2000/count40 that binds each channel’s source clock, error and signed watts. Identity is checked against the installed device; both original entity IDs and the reversed channel1 sign are preserved. No device configuration, HA representation clock, credential or network route changes.

The explicit new revision is `shelly_modbus_source_v2`. Existing `ha_shelly_power_v1` rows and conversion code remain unchanged; no historical source clock is reinterpreted. Row `ts` is the actual observation time after the read; per-channel timestamps are decoded from the meter. Errors, nonfinite power, future/stale clocks, identity/protocol/truncation failure, cross-channel source skew over five seconds, or in-process retrograde clocks deny the total. Source clocks are never replaced with observation time. Repeated timestamps age out at the existing 300-second diagnostic boundary. A failed read inserts an explicit unavailable gap with no source timestamp or cached power.

Monotonic comparison is in-process and resets on an ingestor restart; the timestamp/future/stale checks still apply independently. This is not an across-restart monotonic ledger or an assertion of atomic acquisition across channels. The source response has one-second timestamp resolution; an observed future timestamp is denied even if only a fraction of a second ahead. The first live read demonstrated precisely that negative case, with valid identity/error flags and NULL total; no clock tolerance or source correction was invented.
