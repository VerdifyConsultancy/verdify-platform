# MCP and writer outbound boundary (#1011 / #1022)

The product owns `verdify-outbound`, a two-replica fixed-host relay using the existing digest-pinned nginx image. Application pods have no direct Internet route. Three private service ports expose only OpenAI `/v1/embeddings` (POST), Slack `/api/chat.postMessage` (POST), and Open-Meteo `/v1/forecast` (GET/HEAD). All other paths and CONNECT are refused. The relay selects its upstream hostname from immutable configuration, ignores caller Host/forwarding headers, refreshes DNS every 30 seconds, verifies the upstream TLS certificate and SNI with depth 3 for the cross-signed Open-Meteo chain, and logs neither request URLs nor authorization headers. Its own public-443 NetworkPolicy excludes private, metadata and cluster addresses, so a private DNS answer cannot open a private route.

MCP retains its dedicated non-automounting ServiceAccount and database/DNS paths; only the OpenAI and Slack relay ports are added. The ingestor retains exactly one replica, Recreate and the fail-closed Lease. Its policy grants exact ESP32 `192.168.10.111:6053` and Jason-approved read-only Shelly `192.168.10.36:502`, HA/MQTT `192.168.30.107:8123/1883`, namespace/pod-selected database, MQTT fan-out, Hermes, MCP and Frigate, exact Kubernetes Lease endpoints and the existing individually named read-only infrastructure metrics endpoints. There is no Internet or whole-VLAN CIDR in either application policy. Future dependencies require an explicit source change.

Writer placement keeps the existing `agentfleet.vallery.net/node-class=general` selector and soft avoidance of node6, preserving failover instead of hard-pinning. Read the actual eligible nodes and node addresses immediately before deployment and report them to network-infra#42. Firewall sources must use the observed SNAT behavior; a pod IP alone does not establish the UDM source.

Delivery uses one reviewed implementation and attended full non-pruning sync: relay/Service/identity/policy at wave 0, relay-configured MCP at its existing wave 10, Hermes at 20 and the sole ingestor at 30, then the narrowed caller policies at wave 40. This keeps callers working through their old network policy until their new configuration is Ready. Existing migration/readiness hooks remain active. Preserve the previous release-pin and manifest revision as the rollback source; do not open a diagnostic ESP32 connection or perform an OTA.
