# API direct-light command boundary

The API's greenhouse-scoped light POST has no transport to the owning HA/setpoint writer. Previously it inserted the requested boolean into `v_runtime_equipment_state_write` and returned `recorded`, so command intent could appear as physical runtime despite no delivery attempt. This source disables that unsupported path: valid authenticated requests return HTTP501 `light_control_unavailable`, explicitly accepting no command, without acquiring a database connection. Missing/wrong write keys still fail403; invalid circuits/actions still fail400. The read-only OpenAPI contract declares501 and no200 success.

Only the existing actual-observation paths remain: ingestor/HA readback and the separate internal setpoint server's confirmed HA calls. This change introduces no writer, forwarding, command queue or automatic fallback. Its tests exercise the actual ASGI authentication/routing path with a database that would time out if touched; both circuits, both actions and separate greenhouse identifiers remain side-effect free. Existing authentic-observation and HA failure/confirmation boundary tests are retained. A source/test pass is not deployed acceptance: promote the exact API image through the five release pins, perform the normal no-prune full-hook sync, and verify baked source, digest and running function/route contract read-only. No physical command is required for this disabled result.
