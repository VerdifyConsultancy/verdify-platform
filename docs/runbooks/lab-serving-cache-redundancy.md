# Independent Lab serving caches (#1005)

The public Deployment serves two independent, validated per-pod cache generations. Required hostname anti-affinity separates the serving pods. The publisher retains the original `verdify-lab-site-cache` RWO claim; a private origin Deployment on its cache cohort exports only the already-public tree, committed SHA-256 manifest and redacted publication receipt. It has no public route, credentials, API token or outbound network permission. Only serving pods can reach it; their egress permits only that origin and cluster DNS.

This preserves the existing descriptor-bound public scanner and atomic local directory exchange. Longhorn RWX exposes NFS, whose Linux client rejects rename flags required by this publisher; changing the claim's access mode would not preserve the publication contract. No new PVC, NAS share, S3 credential or storage class is introduced.

Each serving cache reads the committed manifest, downloads or copies regular file bytes into a private candidate, verifies hashes, checks the manifest again and requires a matching publication receipt. The existing public-output scanner holds the scanned candidate descriptors through atomic promotion. A failed transfer, changing generation, rejected public file or unavailable origin preserves the previous validated tree. Initial pods remain unready until the first successful validation. Unchanged generations refresh receipt freshness without re-downloading or rescanning the tree. Refreshes run every two minutes; publication remains on its existing 30-minute schedule. The origin/publisher is a refresh dependency; existing serving caches remain readable during its recovery. This does not make publishing or all storage fault-free.

Transfers have per-file and overall deadlines, bounded file/tree sizes and a 4Gi emptyDir limit per serving pod. The client reuses identical local bytes by copying, never hardlinking a live generation. It does not follow HTTP redirects. Containers use existing immutable images, non-root UID1000, read-only root filesystems, no capabilities and no mounted API token. The publisher image must contain `sync-lab-serving-cache.py`: merge the checked code, wait for the existing in-cluster image build, then promote only its reviewed publisher digest before syncing this source. Do not sync the new template with the preceding publisher image.
