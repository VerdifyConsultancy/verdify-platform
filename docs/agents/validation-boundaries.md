# Current validation boundaries (#322)

## Offline CI

`.agent-fleet/ci.yaml` is generated by the owning Agents registry. Its native
platform checks use a clean checkout, mock device clients and private database
fixtures; they do not invoke `make test`, `make check`, `tests/run.sh`, or the
live feedback-loop script. The firmware compile profile uses public dummy
credentials and is explicitly NONDEPLOYABLE. `make ci` is the repository's
offline source gate, not the live smoke suite.

The existing native `test_device_write_gate.py` entrypoint now includes genuine
production-render controls and deliberately broken fixtures: a second ingestor,
RollingUpdate, a mutable image tag, missing config identity, wrong readiness
route, rendered Secret and disabled Lease. Each negative must fail at its named
invariant, after the same unmodified render passes. Gate tests use mocked device
clients; no ESP32 connection is opened. Source rendering does not prove live
health or running image identity.

## Retained references, classified

- Dockerfiles and Kaniko images are current build contracts, not VM services.
- `test_g5_dualwrite_validation.py` can start a bounded disposable PostgreSQL
  container with dummy fixture credentials; it does not require the destroyed
  Verdify stack. Private PostgreSQL fixtures in campaign CI disable TCP and
  discard production DB environment variables.
- Docker transport tests validate the explicitly selected local developer
  backend with fake executables. They do not discover or connect to production.
- `/srv/verdify` literals in fidelity/observability tests describe existing
  container runtime paths or historical operator proof-file contracts; source
  string comparisons are not host dependencies. They are not silently rewritten.
- Historical docs, source history and obsolete operator lifecycle targets are
  outside the offline validation gate. They receive no current runtime credit.

## Live verification

`make test`, `make check` and `tests/run.sh` are live/operator surfaces and must
not be used as offline CI. Keep their live database/read-only checks distinct
from the offline contract tests. After a production delivery, use the existing
`scripts/k3s-smoke.sh smoke --expected-api-sha SHA --expected-api-digest DIGEST`
and `device-monitor` with the reviewed release receipt and scoped kubeconfig.
Those checks verify service health, source/digest identity and exactly one
existing device socket; source tests do not replace their evidence.
