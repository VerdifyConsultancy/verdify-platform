## Band-Compliance Build Sprint (sprint-2) — Design & Execution

**Branch:** `band-compliance-fw` · **Authority:** ADR0003 §6 (the 7 sprint-2 build decisions) · **Audit:** `docs/reviews/control-story-adversarial-audit-2026-06-17.md` · **Epic:** band-compliance reconcile (#359, BC-1..BC-12).

> Decision-of-record: the control objective for this regime is **band COMPLIANCE — actual tracks the device-truth target curve 24/7 — not energy minimization**. The WIP branch shipped the safe additive half (pinch built but disarmed, BC-5 heat-assist) and left the convergent half undone (pinch defaults to 0 and is wired to nothing; cost-brakes retained; legacy controller still ships; net +240 LOC against a net-negative criterion). This sprint arms tracking, makes off-target drift visible to the grade, makes escalation symmetric, makes dehum a deterministic outdoor-aware bidirectional selector, inverts the wetting ladder to lowest-GPM-first, and deletes the dead second controller — ending strongly net-negative LOC. Firmware is software but the **OTA stays Jason's gate**.

### Overview

The controller is architecturally Jason's clean model (one solar-ephemeris diurnal band curve, one supervisory 8-mode FSM, one single-arbitration allocator, staged hysteresis, no PID) but behaviorally floats inside the wide band — `climate_band_error()` returns 0 anywhere in `[low,high]` (`greenhouse_logic.h:468`) and `apply_band_track_pinch()` (`:420`) ships with `band_track_fraction=0` (`greenhouse_types.h:690`), omitted from the `controls.yaml:586` initializer and absent from the registry/dispatcher — so the OTA binary's tracking behavior is byte-identical to `main`. Sprint-2 closes that and the four follow-on decisions, then executes the deletions.

The hard constraint: **WS-A/B/C/D/E all edit the same three firmware files** (`greenhouse_logic.h`, `greenhouse_types.h`, `controls.yaml`) — they are strictly sequential, not parallel. Additions/replacements land first (each proven by `make firmware-replay-band OLD=main`), deletions land **last** (each proven `=0` against the band-first baseline).

### The test-default trap (load-bearing — verified worse than first stated)

The unit suite runs the **legacy** path two ways: directly via `default_setpoints().sw_fsm_controller_enabled=false`, AND via the misleadingly-named helper `band_setpoints()` (`test_greenhouse_logic.cpp:79-91`), which overrides only the band **edges** and **inherits the false flag** — so a `band_setpoints()`-based test runs the legacy cascade despite its name (proof: `relief_after_sealed_max:1105` asserts `THERMAL_RELIEF`, which `determine_mode_band_first` never emits). Therefore **every new behavioral test in WS-A–D must force `sw_fsm_controller_enabled=true` explicitly**, and WS-E's legacy-test migration must treat **every `band_setpoints()`-using test as legacy** — a grep for `=true` alone misses them. WS-E step 0 makes `band_setpoints()` itself force band-first.

### The 8 workstreams

- **WS-A — pinch as the operating default (ADR §6.1, BC-3).** `default_setpoints().band_track_fraction` 0→0.50 (calibrated) + the `controls.yaml` setpts initializer (authoritative device default) + full plumbing. **Two corrections from the critic:** (1) `apply_band_track_pinch` must add a **width floor** so `band_heat_target_f(pinched)+heat_hysteresis ≤ pinched.temp_high` (and the VPD-cool analogue) — otherwise on a tight pinched band (e.g. a narrow 74–76 prod band at a high fraction) the heater fires above the cooling edge → thrash; the native test must assert this, not merely `temp_low<temp_high`. (2) `replay_emit.cpp` band-derive must populate `temp_target`/`vpd_target` from the **real `crop_band_anchors` temp_target/vpd_target harmonic** (the device target is its own `band_temp_target_*` harmonic per `controls.yaml:422`, NOT the band midpoint and NOT the neutral 75/1.0) or the pinch tracks a wrong shape and the calibration is invalid.
- **WS-B — one shared two-stage escalation mechanism (ADR §6.5).** A single direction-parameterized `stage2_escalation_latch()` used by heat2 (geometry preserved, replay-band=0), the **new** fan2 latch (`cool_stage2_exit_hysteresis_f`), and (via WS-D) the fog→mister edge — killing today's asymmetry (heat2 latches, fan2 was a bare threshold at `:2096`). `fan2_latched` follows the heat2 contract.
- **WS-C — deterministic outdoor-aware bidirectional moisture-exchange selector (ADR §6.4).** Pure psychrometrics + `estimate_moisture_exchange()` replace BOTH the `cold_dehum_allowed` brake AND BC-5's unconditional heat co-run. **Two corrections:** (1) the Magnus constant is **b=237.3** (a single named `GH_MAGNUS_B` — matches the device VPD `es` at `controls.yaml:167`, NOT the dewpoint-INVERSION 237.7 at `:458`; the comment must forbid "correcting" it). (2) the heat candidate's per-cycle temperature rise uses a **named realistic gas-heater dT (~1.5–2.0°F)**, not `heat_hysteresis` (a band, not a rate — would understate heat's gain and mis-select vent on marginal cold-humid rows; the sign is correct, the magnitude matters). `outdoor_cold_for_vent` and its `COLD_VENT_COOL_EXIT_HYST_MIN_F` exit-hysteresis stay (invariant #14).
- **WS-D — fog→misters, lowest-GPM-first (ADR §6.6).** Re-order `MistStage` so FOG is the entry (AquaFog ~0.26 GPM) and misters (~1 GPM/zone) escalate above it; reuse the WS-B helper. The reorder keeps `name==index` (`MIST_NAMES={WATCH,FOG,S1,S2}`) so replay/grafana parse the literals; **both** `prior_action` sites (`logic.h:670` and ~`:811`) must flip together. The fog-only dwell reuses `mist_s2_delay_ms` but must be **calibrated against a night/spike replay slice**, not shipped blind at the 5-min default (a real VPD spike can leave the canopy too dry).
- **WS-E — one band-first controller, net-negative LOC (ADR §6.7).** STRICTLY LAST. Delete the legacy cascade (~470 LOC), `THERMAL_RELIEF` (reindex IDLE 7→6 is **SAFE** — verified the wire publishes `MODE_NAMES[mode]` as a STRING at `controls.yaml:1576`, not the int, so no tombstone fallback is needed), the dwell-gate dead path, the superseded brakes, `bias_heat/cool`, `dH2/dC2`, the no-op shims + registry rows; make `sw_fsm_controller_enabled` non-optional; consolidate the heat↔air interlock into one pure decision helper. Prereq: the test migration above.
- **WS-F — serve the target as one source + audit it (ADR §6.3, data half).** `fn_band_setpoints` gains `temp_target`/`vpd_target` from `fn_crop_band_value` (mig 181, additive); the midpoint derivations in the ingestor writer are retired; `v_band_device_divergence` (mig 182) audits the device-published target. **Prereq (critic):** verify `crop_band_anchors` actually carries `crop_type='house'` `temp_target`/`vpd_target` 4-anchor sets on **prod** — confirmed present in the seed (mig 161, all 6 house series) and retuned by mig 174, but `fn_crop_band_value` returns NULL on an incomplete set, so the single-source test asserts `IS NOT NULL` to avoid a vacuous NULL==NULL pass. No firmware.
- **WS-G — kill saturate-at-1.0 + headline |actual−target| + device-truth homepage (ADR §6.2).** Reshape `fn_grade_credit` (**mig 183** — number fixed everywhere; the v1 spec inconsistently said 181, which collides with WS-F) from flat-1.0-in-band to a tent peaking at the ideal midpoint (IDEAL_EDGE_CREDIT=0.5 at the edges), mirrored byte-for-byte in `daily.py _grade_credit`; add `fn_band_deviation` + `daily_summary` deviation columns as the headline metric; re-quantile-match the mig-147 anchor ladder (the verbatim `$reanchor$` block with `CREATE TEMP TABLE … ON COMMIT DROP`; BC-6 ≥90% ordinal stability); promote the normalized delta homepage panel (id 42) and repoint it onto the device-published target. Does NOT change the arbitration numerator (tracking is the pinch's job). No firmware.
- **WS-H — CI/deploy/OTA staging.** Two CI fixes are **prerequisites**: (1) widen the band-DERIVE gate (`ci.yml:516`) to fire on `greenhouse_logic.h/types.h/controls.yaml` (it currently triggers on `solar.h` only — the pinch is band-derive-blind otherwise, the exact wet-night-shipped-blind trap); (2) **fix the `no-new-fire-and-forget` job (`ci.yml:542`), which is a complete no-op** — its `awk '/^\+[[:space:]]+- id:/'` never matches the real `tunables.yaml` format (`- platform: template` / `id: num_x`, no `- ` before `id:`), so it always passes vacuously and freeze rule 6 is currently unenforced. Fix the extractor (`grep -oE '^\+[[:space:]]+id:[[:space:]]+num_[a-z0-9_]+'`). Add `firmware-twin-sync`; map the gate ledger; deploy the data half via prod-promote → gated `argocd app sync verdify-prod-dark`; stage the firmware "ready for OTA on command."

### Risks

- **Band-derive blindness (headline):** the pinch and ladder live in `greenhouse_logic.h/types.h/controls.yaml`, not `solar.h` — without the WS-H ci.yml gate widening, arming the pinch shows 0 on both the stock replay (corpus-fed band) and the solar.h-only band gate = the exact wet-night-shipped-blind trap. The widened gate + mandatory `firmware-replay-band` is the hard guard.
- **Pinch hysteresis inversion:** a tight pinched band can push `heat_target+heat_hysteresis` above `temp_high`, firing the heater inside the cooling region. Mitigated by the WS-A width floor + the native demand-overlap assertion; the 0.50 default cap reduces but does not eliminate the risk on already-narrow prod bands.
- **`no-new-fire-and-forget` false confidence:** the CI guard was a no-op (vacuous pass); freeze rule 6 was unenforced. PR-9 fixes the awk; until then, cfg presence rests on `test_cfg_readback_sensors_are_routed_to_entity_map` + manual check.
- **Invariant #14 (cold-day vent cap) breach** when WS-C removes `cold_dehum_allowed` (verified tied to #14's condition) — mitigated by the estimator gain-margin + min-dwell + the retained cold-vent exit-hysteresis; if breached on the cold-corpus slice, add a per-mode DEHUM_VENT min-dwell (anti-chatter, ALLOWED), never the reinstated cost-brake. BLOCKING gate.
- **Orchid wet-night regression** if WS-E deletes the brakes before WS-C's heat-assist is live — hard ordering constraint (C before E).
- **WS-F served NULL:** if `crop_band_anchors` lacks the `house` `temp_target`/`vpd_target` rows on prod, the served target silently goes NULL while the single-source test passes vacuously — the `IS NOT NULL` assert + the pre-merge prod count query are the guard.
- **WS-G migration collision:** the v1 spec named WS-G's migration 181 in places, colliding with WS-F's 181/182 — pinned to 183 everywhere.
- **firmware-twin shadow drift** (test_19) — `make firmware-twin-sync` after every firmware commit.
- **Net-LOC is a sprint-level not per-workstream criterion:** WS-C is net-positive on its own (estimator > brake); the negative comes from WS-E; record `git diff --stat` in the WS-E PR.
- **OTA-gate erosion:** nothing in the sprint calls `argocd sync`, scales the ingestor, or runs `firmware-deploy` — the deliverable is STAGED-ready; the device behavior does not change until Jason's gated OTA.
