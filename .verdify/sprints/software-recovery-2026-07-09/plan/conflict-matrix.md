## Required transfers

1. Evidence-core publishes its highest migration number, schema head, cycle view, night view, and replay coverage contract before resource work starts.
2. Resource accounting publishes the stable DB/MCP/API/Grafana head and next migration number before DLI starts.
3. DLI publishes the firmware signal, unavailable schema, and consumer matrix before planner and firmware start.
4. Writer publishes the canonical readback/registry changes and quiet-writer evidence before planner/firmware start.
5. Planner publishes the final registry/bounds and MCP/schema head before the firmware branch is cut.
6. Firmware publishes one immutable binary/replay/heap/rollback packet; release does not rebuild it.

## Collision stop rules

- A lane that needs an **O** surface owned by an unfinished lane stops and requests hand-off; it does not duplicate or cherry-pick around the owner.
- Generated Grafana and schema outputs are regenerated by the last owning lane after rebasing on the preceding merged head.
- Migration numbers are assigned only when a lane becomes dependency-ready; reserved 189 stays with evidence-core.
- No lane adds a tunable/entity outside its accepted issue contract. DLI may add an availability/status signal but not a control knob.
- Any production write outside `release-control` (except an explicitly authorized credential rotation by `security-hygiene`) is an immediate stop.
